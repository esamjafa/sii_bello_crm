# Sii Bello College Module — Codex Implementation Brief

Extend the existing staff-only College module. First inspect the College routes, Prisma schema, unified customer profile, permissions, and immutable payments. Map each requirement to what already exists and implement missing pieces using those conventions. Preserve existing records and the Arabic RTL workflow.

- **Students:** Search by name or contact details. Show contact information, preferred language, status, notes, current and past enrollments, and progress. Show payment history and balances only to authorized finance staff.
- **Courses and classes:** Keep the catalog separate from scheduled classes. Store course description, curriculum, duration, default tuition, and active status. Store class dates, session times, capacity (default 15), assigned teachers, and roster. Prevent duplicate enrollment and overbooking, including concurrent requests.
- **Teachers:** Maintain a searchable directory with contact details, specialties, qualifications, and active status. Link teachers to all courses they can teach. Show actual class assignments separately. Enforce active status and course qualification when assigning a teacher.
- **Finance:** Use ILS and the existing exact-money and immutable-payment models. Track agreed tuition, discounts, full and partial manual payments, refunds, and outstanding balances by enrollment. Record date, method, reference, and staff actor. Use audited reversals or adjustments for corrections and guard against duplicate submissions. Give authorized finance staff filters by date, student, and course. Online payment processing and invoice generation are outside v1.
- **Access and language:** Enforce permissions on the server for student data, payments, and reports. Reuse the unified customer identity where appropriate and keep module-specific records scoped. Preserve Arabic RTL and use the existing translation mechanism for Hebrew and English support.
- **Verification:** Use sample records in a disposable test environment. Verify student creation, teacher qualification, class assignment, enrollment, a partial payment, and balances on both the student and finance screens. Verify that unqualified assignment, duplicate enrollment, overbooking, duplicate payments, and unauthorized financial access are rejected. Run the checks documented in README and report any migration or setup steps.
